# Responsive movement through prompts

Students describe ideas such as "spin in a circle". The workshop skill guides the
interaction, while the basic vex-aim skill uses the standalone CLI's reusable
Bluetooth connection and finite movement helpers. There is no repeated scanning
for every healthy request and no command lesson for the student.

The workshop requires no floor labels, calibration routine, marker arrangement
or extra Python dependency. Keep the current conservative CLI defaults and make
camera snapshots optional. Automatic visual correction is not enabled. Kit-sign
navigation is a separate future capability.

Announce motion, keep a clear level floor and a person near the switch, and reuse
physical readiness within the current interaction. Report measured results
without claiming a physically exact turn from the IMU alone. Never replay an
uncertain movement automatically.

Implementation, limits, timing benchmarks and unfinished hardware acceptance
are maintained in the [CLI movement notes](https://github.com/Tingsters/vexaim-cli/blob/main/docs/motion.md).
The developer benchmark is not a student or instructor setup task.
